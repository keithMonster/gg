# 一天的工作几乎全是回到旧工作:跨天任务密度实测

> 起点:`tracks/keith.md:267` 登记于 2026-04 的认知空洞——「Keith 日常跨天任务密度,monster 路线图 #5 的 ROI 完全依赖这个数」,原测量路径(`harness-engineering/analysis/active-tasks.md`)从未建成,悬置 4 个月。昨晚(08-25)为测 CC 原生记忆水位造出的全机遥测仪器,今晚换个对象直接回答它。track 雷达显示 keith 21 晚窗口内仅 2 次覆盖,是五条对外 track 最低——今晚同时是换向。

## 仪器与对象

**对象**:`monster/threads/*.md`(含 `_archive/`)——Keith+monster 体系的任务账本,一个 thread ≈ 一个任务/事务单元。
**仪器**:git 逐文件提交日期序列。每文件的「真实触碰日集合」= 该文件被 commit 的 distinct 日期,剔除 sweep commits(单 commit 触碰 ≥8 个 thread 文件的批量整形,共 36 个)。
**窗口**:2026-04-20 → 2026-08-25(约 128 天,其中 108 个活跃日)。threads 触碰 commit 共 1769 个,其中 97%(1713)是会话内工作 commit,仅 56 个是 23:00 auto-commit 兜底——账本活动几乎全部发生在真实工作会话内。月度趋势持续爬升:04 月 16 → 05 月 257 → 06 月 392 → 07 月 527 → 08 月 577。

## 读数(全部主会话亲测,python + git)

**存量与跨天率**:361 个被 git 追踪的 thread 文件。**278 个(77%)在 ≥2 个真实日被触碰**;61 个单日;22 个只被 sweep 碰过。

**单任务形态**:跨天 thread 的日历跨度中位 **37 天**(p75=69, p90=94, max=129),但实际触碰日中位只有 **4 天**(p75=9, max=62)。**逐单元占空比中位 ≈ 17%**(验证关订正:初稿写 4/37≈11%,是中位数之比——中位数之比 ≠ 逐单元比值的中位;evaluator 逐单元重算 duty=触碰日/(跨度+1) 中位 0.167、聚合口径 0.156)——典型任务 8 成以上生命期在休眠。

**重入间隔**(同一 thread 相邻触碰日之差,n=1676):中位 **3 天**;35% 次日续;40% 落在 2-7 天;**23% 超过一周;5% 超过一个月**(p90=19 天,max=113 天)。

**日工作面**:每活跃日触碰 thread 数中位 **18** 个(p75=25, p90=37, max=72);其中**当日新建占比中位仅 8%——92% 是回访旧任务**(p25 也有 76%)。

**周组合**:每周活跃 thread 50–116 个,其中 85–95% 是更早周开的。

## 判读

1. **对 4 个月前那个问题的直接回答**:跨天不是任务的一个子类,是常态(77%);「密度」如果按存量问(同时开着多少个)——周粒度 50-116 个。monster 路线图 #5 当年赌的方向(跨会话任务连续性有真实需求)按这组数是全额成立的。

2. **但「密度」是个单位错误**。给连续性基础设施定 ROI,承重变量不是「多少个并发任务」(存量),是**重入事件率 ×间隔分布**(流量 + 视界):这台机器逐活跃日重入数中位 14 次(验证关订正:初稿 ~17 为中位差读法),每次重入要跨越的休眠期中位 3 天、p90 19 天——**记忆/账本基础设施的价值 = 每次重入省下的重建成本 × 1676 次;它的视界要求 = 必须活过 19 天休眠才能接住 90% 的重入**。次日续(35%)是会话缓存能接的;跨周(23%)只有外部账本能接。

3. **体制画像:执行是稀有事件,重入是主事件**。一个活跃日的工作面上,92% 是回到旧任务;真正「开始新工作」中位每天只有 1-2 个 thread。这个体制的支配性成本不是做任务,是**回到任务**——上下文重建是按重入次数计费的固定成本。工具生态几乎全部为「做」优化(首次体验、生成质量),而这台机器的事件分布里「回」是「开始」的 11 倍。

4. **与昨晚 #217 的合拍**:同一条定价律的两极。昨晚测的是风险侧——CC 原生记忆器官事件流被截断,风险计价 ×0;今晚测的是价值侧——截流者本身(threads 账本)每月放电 500+ 次,价值计价全额兑现。「截流」从结构论断变成了有流量读数的实测:被截走的事件流不是消失了,是以每日中位 18 次的功率流进了自建账本。

## 仪器边界(诚实栏)

- 「触碰」= 写 commit。**纯读式重入(翻账本回忆、不改文件)不可见**——故 92% 回访占比对读通道是下界;但反向,账本仪式性小维护(done skill 反哺等 <8 文件的更新)未被 sweep 过滤,会把「触碰」略微虚高,两偏未定量对消。
- thread 文件 ≠ 任务 1:1——部分文件是长寿域账本(cg-infra 类),拉高跨度分布;「77% 跨天」严格说是**账本单元**的跨天率。重入结构本身不受粒度影响。
- 「会话内 commit」含 cron 触发的会话,组织层读数(Keith+agents 有机体),非 Keith 亲手键入数——但连续性基础设施服务的正是有机体整体,ROI 相关层就是这层。
- 单机 n=1,单账本体系;无账本外任务(纯口头/纯 CG 内网)不可见。
