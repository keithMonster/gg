# AGENTS.md 平台事实副本裁决

## 给父会话的最终输出

### 总裁决

**AGENTS.md 该承载平台行为约束，不该承载平台事实值。** 上午那一刀不能外推的直觉是对的，但真正的分界不是「自动加载 vs 主动 fetch」，而是：**分发副本的裁决轴是注入面的在场性收益，不是同步可行性**。

- 上午案（ENGINEERING-STANDARD.md / PLATFORM-SERVICES.md）：不在自动加载链 → 在场性收益 = 0 → 副本存在无收益，任何同步链（version 字段 + 传感器 + 广播脚本）都是纯自指开销 → 删副本正确。
- AGENTS.md：startup 注入 → 在场性收益 > 0（L3b 召回）→ 正确动作不是删副本，而是**把副本降格为机器管理的缓存**：canonical 单源生成、owner 脚本 BEGIN/END 整块盖写、hash 失效检测。同时把收益恒为零的部分（具体当前值）从缓存里删掉（canon 36）。

**为什么 hash 传感器不重蹈自指陷阱**：上午链的自指在于 version 字段是为检测而加的内部状态、检测对象是语义级不可机械判的；hash 从内容直接算（无新增状态），检测的差由外部现实（canonical 真的变了 / 广播真的漏跑）制造，且字符串比对机械可判（essence `mechanical-gate-needs-machine-detectable-target`）。

**漂移危害不对称（本案独有发现）**：82 处里最毒的不是过时事实（误导），是**过时豁免 / 过时授权**（教唆）——cg-patent-agent 的「不再做二次校验」每天 startup 被重新注入，等于持续给 AI 发一张已废止的免罪牌。事实漂 AI 会在响亮失败中自愈，豁免漂 AI 会自信地违约且本地全绿。这条不对称正是「哪些内容必须机器管理」的判据来源。

### 机械判据（对 38 种块逐块三问，可脚本化）

**Q1 真源归属**：这句话的真值源在本仓吗？
- 是（仓专属逻辑 / 本仓架构决定）→ **留**，本轮只修错。18 种仓专属块里嵌的平台事实句子剥出来走 Q2。
- 否（真源在 cgx / 平台 / 模板）→ Q2。

**Q2 值剥离（canon 36 直套）**：块内的具体当前值——数字（1173 张表 / 6 字段）、编号上限（契约 1–7）、版本号（claude-sonnet-4-6）、文件名（server/.env）、规格细节全文（13 行身份校验）——**一律删值**，改成「由 X 决定」+ 取值方法（回源命令 / cgx §N 指针）。值的在场性收益恒为零（AI startup 不需要知道表数），漂移窗口恒为正，删值后「值漂移」从定义上消失。

**Q3 在场性判定**（剥值后剩下的行为约束 / 操作序列）：违反它时，失败信号是否在**同一会话内**响亮出现？
- **静默违约型**（信号延迟到部署后 / 生产 / 平台侧：直连 minio 本地绿灯、自持 key 照跑、去掉 token 校验照跑、漏 fetch 的 push 不报错、身份校验规格写错要到上线才炸）→ 必须在场 → **F2 机器注入块**：进 canonical 单源，owner 脚本整块盖写分发，配夜跑 hash staleness 传感器 + 合成违规反向验证（canon 28：没被人为造过阳性的哨与哑火同形）。
- **响亮失败型**（同会话即报错：凭据文件名错 → 当场连不上，AI 会 ls 自愈；旧参数被服务端拒 → 当场报错）→ 不需要在场 → **F1 恒定指针**：合法性测试 = 「canonical 明天改了，这段文字需要动吗？」不需要才合法（即上午那一刀的形态）。

F2 注入块内部同样服从 Q2：块里只放行为禁令 + 指针（「/api/* 必须过平台 token 校验，规格见 cgx 契约 9，禁自行实现变体」），不放规格细节全文——历史上炸掉 cg-skillhub 全站的正是复述的规格，那是复述的罪证不是保留复述的理由（canon 21：副本忠实复制一个错误规格时漂移传感器全绿）。

### 本轮动作边界

1. **不逐条改对 82 处再等下轮漂——一次做结构改造。** 逐条改对的产物（手写正确副本）在新结构里不是合法形态，改对了也要被重写一遍，纯白做。顺序：canonical 侧定稿 F2 块内容（改正即融在定稿里）→ owner 脚本扩块 → 29 仓整块盖写 + F1 化删值换指针，一次跑完。
2. **20 种「当前对齐」块：动。**「当前对齐」是时间切片巧合，结构上与 82 处同类，不动 = 留下一批未来的 82 处；本轮授权在手、脚本要扩块，边际成本最低点就是现在。
3. **模板仓一并修**——模板旧 = 每个新 fork 出生即旧，且模板是 F2 块分发的第一消费者。
4. **违约级 3 条单列，不许被「文档已修」吞掉**：文档宣称 ≠ 代码现实，先核代码实况（patent-agent 是否真去掉了校验 / yangfan-board 是否真直连 minio / cg-ppt 是否真自持 key）。代码真违约 → 独立整改项挂账（超出本轮文档动作）；仅文档违约 → 随本轮改。
5. **最便宜一击**：广播 29 仓前，先挑 1 个仓做全套改造样板（Q1–Q3 全走一遍），人肉核对后再放量——对齐 monster 自己的「批量外部写先验首条消费端再放量」。

### 问题 4：注入式分发的定性

**不是同病换皮，是对的形态缺了失效检测半边。** 注入块已把「38 种块 × 29 仓的语义漂移」压缩成「块 hash vs canonical 生成 hash」一个机械标量——这是它与手写副本的本质差。但它当前是纯 push 型、依赖人跑，漏跑即永久旧版且零告警（2 仓停在旧 `app` 参数即证）——这恰是 essence `omission-failures-evade-event-driven-sensors`：「该做没做」不产生事件，事件驱动抓不到，出路是周期抽样。补法：夜跑加 `agents_block_staleness`（逐仓比对注入块内容 hash vs canonical 当前生成 hash，机械比对，同时抓漏跑与仓内手改），落地即造一次合成违规验证阳性（canon 28）。**只报数不自动修**——自动修是又一层机制，报给夜巡挂账即可。

### 被排除的补集（采样过）

- **harness 层 startup 自动 fetch canonical**：网络依赖进 startup 链 + AGENTS.md 注入约定不归我们改 → 排除。
- **全删靠 CI 事后拦截违约**（如检测直连 minio 的 import）：值得作为 F2 的补强层（事前在场 + 事后机械闸是两层，不互斥），但 CI 拦截半径有限（key 自持 / 校验缺失不易静态检出），不能替代在场性 → 不作为主方案。

## 元属性反思

**核心假设**：① L3b 在场性收益对「静默违约型约束」真实存在且显著（依据是 monster 自己的实测「会话开头召回 100% vs 长文中段个位数」，但那是 monster 的实验，AGENTS.md 注入位置的召回率未独立实测）；② owner 脚本扩块的执行成本可控（我没读脚本源码，按父会话描述「已有 BEGIN/END 注入形态」推定可扩）。

**可能出错的地方**：静默/响亮的二分在个别块上可能判错（如旧参数「服务端还认不认」决定它属哪类）——判错的代价不对称：错把静默判响亮 → 丢在场性 → 违约风险；错把响亮判静默 → 多占注入块行数 → 仅上下文税。拿不准时偏向 F2（宁多占行数不丢约束）。

**推理盲区**：我没实测 29 仓 AGENTS.md 的总行数预算——F2 块若膨胀，startup 注入本身会稀释 L3b 召回（长上下文中段效应反噬），注入块应有行数硬顶（建议 canonical 侧给 F2 总预算上限，超了就是「该进 CI 不该进在场」的信号）。

**根因预判**：这病的根不在 fork 仓，在模板仓——模板出生时就把平台事实以手写正文形态带进每个 fork。结构改造后模板只应含 F1 指针 + F2 注入块占位标记。

**北极星触达**：决策超越直觉（depth）——父会话直觉「不能直接外推」是对的，本裁决把直觉换成可机械套用的三问判据。

**essence 对齐自检**：`anchor-value-in-activation-not-in-content`（AGENTS.md 的价值恰在 startup 激活机制，grep 过）✓；`mechanical-gate-needs-machine-detectable-target`（hash 可判 / 语义不可判是注入块合法性的分界）✓；`omission-failures-evade-event-driven-sensors`（漏跑广播 = 缺席型失败，周期抽样解）✓；`invariance-allocation`（F1 合法性测试 = 把不变性分配给指针文本而非事实值）✓；`fallback-detectability`（漏跑零告警）✓。反向打我的滴：`separation-need-is-not-topology-verdict`——「先试最轻治理形态」会否否掉 hash 传感器？不否：传感器是对既存机制（注入块）补失效检测，不是新造墙。对齐度：高。
