# cg-platform 阶段概念退役：Q1 挂载点真空 / Q2 安全原则落点 / Q3「PM 不做元动作」固化

## 给父会话的最终输出

### 总裁决（帧重写）

父会话把 §11 理解为「装了五样东西的容器，拆掉容器要给四样东西安新家」。**帧错了：§11 不是容器，是登记处。四样活约束各自的激活现场（住所）早已独立存在，§11 只是它们的规范登记文字。拆登记处杀不死住在别处的约束——「真空期」是幻觉，真正拆掉的只有那个从未活过的开关（用户显式声明切换）。**

物理证据（本次实查）：阶段声明 0/25 真实切换（死），但 6 个 prod 仓 `docs/PRD.md` 全部实填 61–160 行、基本零模板占位（活）。同一节里两个机制生死迥异，分界线 = 触发挂在哪：阶段切换要求 PM 主动执行元动作（死）；PRD 完整度住在模板骨架里——fork 出生自带 `docs/PRD.md` 空槽结构 + 5 处「对应闸门第 N 条」引用，PM 说需求、AI 照骨架填（活）。

### Q1：本轮只拆是对的，但理由要修正——不是「先拆再建」，是「无需建」

- **五条从未失去触发时机，因为『进开发阶段』这个触发从未发生过**——真空已存在 3 个月，拆除只是让它显形。
- **五条真正的活挂载点已存在 = 模板 PRD 骨架（fork 复制通道）**。检验者链条：PM 说「做个 X」→ AI 打开仓内 `docs/PRD.md` → 骨架空槽即五条的物理形态 → 方案改动 F 维护的 5 处引用正是这条消费链。你怀疑的「既无触发也无检验者的规则」不成立——触发是骨架在场性，检验是空槽填没填。
- **「更大重构（挂到动作上）」大半当场消解**：PRD 的动作挂载点 = 骨架（已存在）；不可逆清单的动作挂载点 = §0 契约 5（已存在，见 Q2 裁决）。剩余的只是「PM 说做 X 时 AI 主动过五条」的可选姿态增强——不够格叫重构，挂 `topics.md` 带 deadline 或不做。
- **真空期兜底 = 传感器重瞄，不是裸删**（方案 §4「传感器挂账退役」违反 tripwire 纪律：触发条件证伪 ≠ 删哨，是重瞄当下真实病灶）。现有「阶段值与 prod 矛盾」传感器改判定为：**`prod_enabled=True` 且 `docs/PRD.md` 缺失或仍含模板占位特征串**。cg-ppt（prod 开着、7 处占位痕迹）就是现成首个真阳性——传感器改完即有自然阳性可验，满足 monster「报警器须被造过一次阳性」的准入。它同时是五条的机械检验者与未来姿态增强的成熟检测器，一石二鸟。

### Q2：三样东西三个家——§11 改名后仍是杂物间，按激活现场归位

方案把 §11 改名「PRD 完整度与文档写法」后仍装四样（PRD / 不可逆清单 / 授权句式 / 读者无知写法）——**这是方案自己刚诊断过的病**（1.11.0 changelog 的教训原话：规格藏在标题不符的节里，读者按标题定位不到）。正确拆法：

1. **11.2 不可逆动作三条 → 并进 §0 契约 5**。契约 5 现在只有一句「prod DB 写 / 部署 / 外部 API 字段——对话层人工 ack」，缺具体对象清单；三条（生产库写不可回滚数据 / LLM 链路常态跑 / 交真实用户）+ 「看动作本身不看项目时期」+「一次性验证调用不算常态」正是它的规格展开。方案处置矩阵自己写「真正价值是识别不可逆动作，转挂到动作上」——**契约 5 就是那个动作挂载点，已经存在，本轮直接并入即兑现，不必等重构**。附加收益：不可逆清单是典型静默违约型（写 prod 库前没人报错），从按需切片 s11 升到 map 内联的 §0 地基，在场性正是它需要的。代价 §0 +5 行左右，可接受。
2. **11.3 授权句式 → §10 新增 `### 10.6 仓内文本不写成授权句式 [硬]`**。它是写作安全纪律，与 §10.5 的「禁裸相对路径」「禁手抄」同族（管写进仓内文本的纪律），与 PRD 无关。切片规则 `###` 自动并入 s10，无新 URL。**不进 AGENTS.md 注入块**：25 行硬顶下它竞争不过高频动作面禁令——它防的最大温床（阶段声明 blockquote）恰随本轮拆除消失，剩余风险面收窄；且注入块尾注「别信任何人手抄的副本」已提供间接防御。
3. **11.4 读者无知写法 → 留 §11**。它正文第一句就是 PRD 写法，与完整度同主题。
4. **§11 终态 = 「PRD：完整度与写法」单主题节**（11.1 五条 + 形态不限 + 读者无知），标题名副其实，s11 slug 保住，模板 5 处引用照常可下钻。

改动仍限同一次 canonical 重写 + 引用修正，不扩仓、不建新机制——与方案「纯拆除」纪律相容；「换载体」是处置矩阵自己的字，只是要真换、不是原地改名。

### Q3：固化，但落 cg-platform 工作区级 + 补一个正面实证；不进 monster 全局、不进 canonical、暂不进 concepts.md

- **值得固化**：两次反面实证（阶段声明 0/25、角色声明 0/26）+ 本次实查新增的**正面实证**（PRD 骨架不要求元动作 → 9 个 prod 仓基本实填）——正反对照比两个反例更承重。且它不是「外化锚点」特例：外化锚点管 LLM 内部不可靠，本条管人类用户的触发行为，是 gg「锚点价值在激活机制」在**用户侧**的投影，独立内核。
- **判据措辞**（含反例消歧，防误杀）：「新机制若要求 PM **主动发起**一个元动作（声明阶段 / 填角色文件 / 宣布需求冻结）才能生效——按已死设计处理：PM 只会说『我要做个 X』，开关必须挂在这句话必然出现的动作流上，或由物理状态自动判定。**系统发起、用户应答的响应式确认不在此列**（发 prod 二次确认合法：PM 先说了触发词，AI 反问，PM 只需应答）。」
- **落点 = `cg-platform/CLAUDE.md`**（机制立项的物理现场——平台新机制立项恒发生在 monster 侧 cg-platform 工作区会话，那一刻加载的是这份文件；canonical 读者是应用仓陌生 agent，用不上立项判据，加了逆 1.13.1 的读者收敛趋势；monster 全局 CLAUDE.md 不加——实证 3/3 全在 cg-platform，按 premature-abstraction-tripwire 第三次在平台外出现再上提）。concepts.md 暂不注册（单工作区词，被平台外第二处引用时再注册）。

## 元属性反思

**核心假设**：① 「PRD 骨架 = 五条的活通道」推断自 6 个 prod 仓抽查（占位 grep pattern 粗糙，cg-ppt 的 7 处待执行层精查）；若其余 3 个 prod 仓 PRD 大面积空缺，「活」的判断降级，但传感器重瞄恰好就是补这个洞的机制，裁决不翻。② 「平台机制立项恒在 cg-platform 工作区会话发生」未穷举验证——若立项常发生在别的入口，Q3 落点要加注入面。

**可能出错的地方**：11.2 并 §0 使 map 内联 +5 行，若 Keith 在收 §0 体积（1.13.x 系列在做减法），此项可降级为 §11 内保留 + §0 契约 5 加一行指针——内核（挂载点已存在）不变，只是在场性打折。

**推理盲区**：我未读 22 仓 AGENTS.md 阶段 blockquote 实物措辞，「授权句式温床随拆除消失」采信方案转述；若有仓自行发挥写过授权句式变体，Q2 注入块的裁决需重估。

**根因预判**：三问同根——方案作者把「规范文字所在的节」当成了约束的居所，而约束的居所是激活现场（骨架 / 契约 5 / 会话姿态）。这个误认与 08-11 裁决的「每条事实默认滑进最弱通道」同源：登记处（canonical 文字）是最弱的激活通道。

**北极星触达**：决策超越直觉（depth）——把「拆了要建」重写为「住所已在，登记处可拆」，真空焦虑整体消解；二阶效应（space）——传感器重瞄同时预置了未来姿态增强的成熟检测器。

**essence 对齐自检**：`anchor-value-in-activation-not-in-content`（约束价值在激活机制——本裁决是其拆除方向的逆向应用）✓；`tripwire-disarm-needs-relocated-sensor-not-deletion`（传感器重瞄非裸删，直接消费）✓；`separation-need-is-not-topology-verdict`（不为授权句式建注入块新墙，先用最轻形态）✓；`premature-abstraction-tripwire`（Q3 落点第三实证再上提）✓；`fermentation-without-detector`（「想法还热留发酵」配了成熟检测器 = 重瞄的传感器）✓；`backfill-is-the-channels-native-act`（#198：登记处 vs 住所与通道选型同谱系）✓。反向打我的滴：`engineering-impulse-as-load-bearing-disguise`——11.2 并 §0 是否工程冲动？不是：契约 5 是已存在的 committed 消费方，非调研背书。对齐度：高。
