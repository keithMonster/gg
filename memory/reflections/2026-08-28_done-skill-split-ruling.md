# 2026-08-28 · done（dd）会话复盘机制拆分裁决

## 给父会话的最终输出

**总裁决：该拆，但切分维度不是「按 step 拆成多个仪式」，而是按「唯一可靠捕获时刻」把 done 的角色从『首次捕获仪式』降级为『对账 + 执行仪式』。零新 hook、零新定时任务，唯一新增物是 dd 的一个轻档入口。**

**先订正简报一个数字错误（改变整个前提）**：简报「done 日志 114 份」是**目录数（天数）**，实测 `find` 总份数 **1487**，最近 30 天 **423 份**——对 816 个 transcript 覆盖率 ≈ 52%。done 不是低覆盖通道；真病是**覆盖有偏**：有 diff / 有执行动作的会话 done 常跑，纯讨论态会话（ai-memory-evolution 08-25 物证：聊透形成处置意向、零文件改动、全仓零痕迹）done 结构性不跑。而恰恰是这类会话，信息**只存在于对话里**（无 git 留痕可反查）——留痕机制的触发概率与信息的不可再生度**负相关**，这才是 done 作为捕获机制的结构性失效面，比「撞压缩」大。

**切分线（按唯一可靠捕获时刻分三类）**：

- **A 捕获类 → 时刻 = 事发即刻，载体 = 直接写消费路径**：失败史（canon-bugs）/ Keith 纠正 / 能力缺口挂账 / 讨论态结论。monster 已有两个成立先例：「纠正即落库」（Step 5D 提前到纠正当下）+「缺口 62% 蒸发 → 挂消费路径」。事发时锚（全部捎带在既有条款上，不建新 hook）：canon-bugs 挂 ER#5「同一问题失败 2 次」的修复确认时刻（症状词还在屏上，末尾补写丢细节）；缺口挂「撞上第 2 次」时刻（对齐 essence `recurrence-defense-pays-on-second-occurrence`）；纠正已运行不动。**done 对应 step（5D/5F/6）降为对账**——「核一下本轮该写的写了没」，不再是首次捕获。
- **B 执行类 → 时刻 = 会话末，留 dd 原地不动（dd 的不可拆内核）**：Step 0 未闭合盘点 / 0B 余值盘点 / 7 归档 / 8 worktree merge / commit。它们消费的是活工作区与热上下文本身，别处物理做不了。0B 不是记忆资产，是执行动作（否掉简报把它并入「资产捕获」的隐含归类）。
- **C 教学/审计类 → 留 dd**：Step 9 quiz 拆出去要新触发器，存在税 > 收益；讲解段的「记忆写入过目窗口」审计功能保留在 dd 对账段——事发即刻写入的条目也在此汇总过目，Keith 的审计窗口不减反齐。
- **D 叙事类（Step 1/2/4 日志部分）→ 留 dd**：成本低、有 done_fidelity 探针和跨会话接手当消费者。砍薄是另案，不属本次拆分。

**唯一新增物：dd 轻档入口**。讨论态结论没有机器可判的事发锚（「聊透了」不可机械判定，`mechanical-gate-needs-machine-detectable-target`），诚实结论是这属于机制不可达域——解法不是建机制，是给 Keith 一个最便宜的手柄：讨论收束时说「落一下 / 落库」→ 只跑写入 + 对账（5D/5F 及必要的 7 最小归档），不跑 0–9 全套。这与「dd 必须原地跑」invariant 完全相容（同会话内、prompt cache 全命中）。

**撞压缩的处置：拆分后不需要任何压缩保护方案**。A 类已在事发即刻入库，压缩伤不到；B 类执行依赖的是当场可查的物理状态（git status / worktree 路径），压缩后照跑；受伤的只剩 D 类叙事质量——可接受代谢。precompact 卡片方案族不必再投入。

## 核心假设

1. 「事发即刻写入」挂在既有条款（ER#5 / 第二次撞缺口）上的 L2 捎带锚能被执行——这是外推，纠正即落库的先例支持但那条有 Keith 在场的信号词，ER#5 场景没有。
2. 423/816 的覆盖率把 subagent transcript 也算进了分母，真实「主会话覆盖率」可能更高——方向不变（覆盖有偏成立），但 52% 这个数不能承重。
3. 讨论态会话的价值密度足以值得一个轻档入口——单靠一个 SkillOpt 案例（n=1）。

## 可能出错的地方

- A 类降为对账后，若事发即刻写入实际执行率低（L2 锚被漏），对账段就成了唯一防线——而对账依赖 dd 被触发，回到原点。观测哨：canon-bugs 新条目的写入时间戳 vs 会话结束时间戳的分布（事发写应显著早于会话末）。
- 轻档入口可能被滥用成「全档 dd 的逃票通道」（执行态会话也只跑轻档，Step 8 merge 被漏）——判据应写死「worktree / 未 commit 改动存在时轻档拒绝受理，指回全档」。
