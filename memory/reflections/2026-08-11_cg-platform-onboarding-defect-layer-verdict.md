# cg-platform onboarding 缺陷四类：修复层落点裁决

## 给父会话的最终输出

### 总裁决（框架重定义）

父会话把问题框成「每类缺陷选一个修复层 + 独立决定是否回填」。**框错了半边：四类缺陷不是四个独立的层选择题，是四条不同分发通道各自的病；「是否回填」不是独立自由变量——它由该事实所属通道的原生分发动作决定。** 修通道之前不回填内容；在错误通道里手工改对 19 份存量是白做（08-06 裁决同款：逐条改对的产物在新结构里不是合法形态）。

cg-platform 现存四条事实分发通道，强度递减：
1. **远程 URL**（platform-map.md）——即时生效、全 fork 自动获得、读者恒可达
2. **注入块**（owner 脚本盖写 + hash 检测）——重跑即刷新
3. **fork 复制**（模板 → 出生快照）——出生即定格、永不回流
4. **手写副本**——已被 08-06 裁决处决

**通道选型判据：变化频率 × 违约响亮度。** fork 后还会变的规范级事实 → 远程；会变且静默违约 → 注入块（值剥离、动态生成）；fork 后合法归仓内演化的 → fork 复制；具体当前值 → 不落任何副本，恒动态回源。

### 逐类裁决

**缺陷 1（无启动入口）：落平台地图新增「本地启动（骨架默认）」一节，仓内只许一行 delta。零回填。**
- owner = 平台方：19 fork 启动同构不是巧合，是骨架契约的产物——「骨架默认怎么跑」是规范事实，不是教程叙事。「地图定位是规范不是教程」的反对不承重：§10.0 没有 GETTING-STARTED 位置，恰说明该位置应在平台侧开一次，而不是 19 仓各开一次（那才是 §10.1 禁的复述）。
- TEMPLATE.md 不是落点：它服务「正在 fork 的 AI」，fork 完成即失效——而启动指南的读者是 fork 完成后进仓的人/AI。
- 仓内 delta（启动方式偏离骨架默认的仓）真源在仓内，写一行 + 指针，§10.1 完全兼容。
- 回填 = 零动作：远程通道全 fork 即时获得。

**缺陷 2（.env.example 残留）：模板仓修是止血必做（③ 是活繁殖源）；存量 19 仓回填做，脚本机械批量，先 1 仓样板再放量。**
- 分级：①孤儿注释 ②死字段 = 垃圾级；③ ENV_NAME=test 配 prod 域名 = **危险级静默违约**——本地开发打 prod API，本地全绿、副作用落 prod 侧，正是 08-06 判据里「必须修」的那一类。模板本体 AUTH_PAGE 示例值就是 prod 值 = 每个新 fork 出生即带此病，cg-skillhub 逐字照抄就是繁殖证据。模板改法：示例值换 test 值或 `<按环境填>` 占位，杜绝「照抄即错」。
- 回填裁「做」的证据：19 仓只有 cg-runtime 一个自愈（1/19），「随各仓自然迭代」实测 = 不修；且 ③ 危险级不等。①② 本可只修模板不回填，但既然 ③ 逼出一把批量脚本，①② 搭车边际成本≈0。
- 不建同步机制：.env.example 的本性就是出生快照 + 仓内演化（各仓加自己字段是合法的），病只在出厂内容，修繁殖源 + 一次性刷新即止（essence `separation-need-is-not-topology-verdict`：先试最轻治理形态）。
- PM 冲突面：.env.example 是平台契约面非业务面，冲突≈0；仍按 monster 惯例改前 pull + 先 1 仓样板。

**缺陷 4（逻辑路径引用）：C 的两个选项都不对——问题不是写法也不是规则例外，是被承重引用的文件对读者物理不可达/不可 resolve。正解 = 把被引内容搬到读者可达通道，再机械改引用。**
- integration-contract.md 物理在 monster/cg-platform/（Keith 本机运维仓）。应用仓 AI 按地图规则 resolve `cg-platform/...` → 仓内查无此文件 → 放弃或幻觉。「地图补例外规则」只让路径语法合法，文件照样够不到——修标签不修物理。「改 19 处写法」指向一个不可达文件同样白改。
- 分叉判据（需父会话核一个事实：应用仓施工是否恒发生在 Keith 本机）：若 PM 环境的 AI 也会读 → 被引的「字段 SSOT」内容必须上远程（并入 platform-map 或独立 URL），与平台既有「规范权威源 = 远程」范式一致——**推荐此解**，即便施工当前恒在本机，它也是与产线一致、不随施工地点漂移的形态；若确认恒 Keith 本机且接受该耦合 → 降级解 = 绝对路径 `~/githubProject/monster/cg-platform/...`（monster 跨项目惯例），省一次上远程但把可达性绑死在单机。
- 回填：引用替换是特征串机械改，脚本批量，先 1 仓样板。
- 顺手把坑变规则：地图补一句「跨仓引用一律完整 URL / 明确前缀约定，禁裸相对路径指向非本仓文件」——写在主干一处，合 §11.1。

**缺陷 5（注入块 13→14）：修注入脚本的 canonical→真源那一跳——不是把 13 改成 14，是删值。**
- 「13 个主题」是具体当前值，08-06 判据 Q2 已裁：值恒不入注入块。改 13→14 = 修文本不修机制，第 15 个主题出现照旧过时。正确形态：注入脚本生成时从真源（DB/registry）动态数出，或剥成「主题清单回源命令」指针。
- 本缺陷还免费暴露了一个传感器盲区：hash staleness 只测「fork 与 canonical 一致」，测不出「canonical 与真源一致」（canon 21 同构：副本忠实复制错误内容时传感器全绿）。动态生成把这一跳从「需要传感器」消成「不存在」——比加传感器更硬。
- 回填 = 重跑注入脚本，通道原生动作，零额外成本。

### 对 A/B/C 三问的直接回答

- **A（回填总裁决）**：不是「回填 vs 自然迭代」二选一——按通道分：缺陷 1 零回填（远程自动）、缺陷 5 重跑注入（原生）、缺陷 2/4 脚本机械批量（先 1 仓样板再放量）。手工逐仓改 19 次这个选项在所有缺陷上都不存在。
- **B**：owner = 平台地图（骨架默认启动一节）；仓内只写 delta。
- **C**：两选项皆错，正解是可达性迁移（推荐上远程），见上。

### 执行顺序（父会话侧）

1. 模板仓修 ③（止血繁殖源，最高优先——每天都可能有新 fork 带病出生）+ 清 ①②
2. 平台地图加「本地启动」节 + 「跨仓引用禁裸相对路径」规则
3. integration-contract 被引内容上远程（或父会话核实施工恒本机后选绝对路径）
4. 注入脚本改动态取数 + 重跑全量注入
5. 存量批量脚本（.env.example 修正 + 引用替换）：1 仓样板人肉核对 → 放量 19 仓

## 元属性反思

**核心假设**：① 「PM 环境 AI 会读应用仓引用」未实证——若施工恒在 Keith 本机，缺陷 4 的严重度从「悬空 SSOT」降为「路径规则误判」，但两种世界的修法收敛（可达性迁移），裁决不翻。② 19 fork 启动「基本同构」采信父会话实查，未逐仓验证 delta 规模——若 delta 普遍很大，「地图写默认 + 仓内 delta」的比例会反转，但结构不变。

**可能出错的地方**：缺陷 2③ 的「本地打 prod」危害等级依赖「那些 prod 域名端点有写副作用」——若 VX_API/AUTH_PAGE 全是只读端点，危险级降为垃圾级，回填从「必做」降为「搭车做」；但回填动作本身不变（反正脚本要刷），错判不改变行动。

**推理盲区**：我没读 ENG-STD §10 全文，「§10.0 无 GETTING-STARTED 位置」采信父会话转述；若 §10 另有「平台地图不得扩节」类约束，缺陷 1 落点需重议。

**根因预判**：四类缺陷同根——模板 fork 是唯一出生仪式，但平台没有「哪类事实走哪条通道」的显式选型表，每条事实默认滑进 fork 复制（最弱通道）。执行顺序 1-4 修的是四个症状，选型表进平台地图才是断根。

**北极星触达**：决策超越直觉（depth）——把「每类选个层」重写为「通道选型 + 回填是通道原生动作」，回填问题整体消解。

**essence 对齐自检**：`presence-benefit-splits-replica-verdict` #192（副本裁决轴 = 在场收益；本案缺陷 5 直接消费其 Q2 值剥离）✓；`anchor-value-in-activation-not-in-content`（启动指南的价值在读者可达的激活位置，非内容本身）✓；`separation-need-is-not-topology-verdict`（.env.example 不建同步机制）✓；`mechanical-gate-needs-machine-detectable-target`（批量回填全部限机械可判改动）✓；`bug-shape-survives-fix`（改 13→14 = 修文本不修形态的活体）✓。反向打我的滴：`engineering-impulse-as-load-bearing-disguise`——「通道选型表进地图」是否工程冲动？不是：四类缺陷已是四个 committed 消费实例，非调研背书。对齐度：高。
